# Dynaconnective DY-UD200

## 1. 概要

| 項目 | 内容 |
|---|---|
| USB ID | `1c11:1004`（USB 2.0 High-Speed、バスパワー 500mA。`lsusb` では別のメーカー名が出ることがある） |
| 放送波 | 地デジ（UHF 13〜62ch・VHF 1〜12ch・CATV C13〜C63ch、ワンセグも可） |
| チューナー数 | 1 |
| B-CAS | 本体のスロット（外付けのカードリーダーも可） |
| ファームウェア | 本体に入っている。初期の版と再販品の `1.0.5-2` の両方に対応 |
| Linux | [recdyna](../README.md) |
| Windows | [BonDriver_Dyna](https://github.com/waya0125/BonDriver_Dyna) |
| 公式ページ | なし（メーカーは 2010 年 10 月に自己破産を申請） |
| 有志の資料 | BonDriver_dyud の配布ページ（[Wayback Machine](http://web.archive.org/web/20130527152129/http://dyud200.zxq.net/)）・[まとめ Wiki](https://w.atwiki.jp/dy-ud200/) |

本ドキュメントでは DY-UD200 の USB 制御プロトコル・暗号化と復号の仕様（制御コマンドの AES-ECB と TS の XOR）・内蔵 B-CAS スロット制御・Linux 実機での検証結果をまとめています。  
プロトコル仕様は、有志の Windows 用ドライバー **BonDriver_dyud v8.5.3**（2010 年公開、旧配布元 `http://dyud200.zxq.net/`、Wayback Machine 2013-05-27 アーカイブ）のソースコードを参考に Go で再実装しています。

## 2. 準備

1. udev ルールを置きます（[README の「準備」](../README.md#準備)）。
2. B-CAS カードを本体のスロットに挿します。  
   外付けのカードリーダーを使う場合は、`pcscd` を動かしておきます。

## 3. 使い方

```bash
bin/recdyna --check 21                          # 選局・ロック・信号強度の確認だけ
bin/recdyna --b25 --strip --stats 21 30 out.ts  # 内蔵の B-CAS で外して 30 秒録画
bin/recdyna --b25 --pcsc --strip 21 30 out.ts   # 外付けのカードリーダーで外す
bin/recdyna --b25 --strip 21 - -                # 標準出力に流し続ける（Mirakurun などから）
```

オプションと Mirakurun の設定例は [README](../README.md#使い方) にあります。

## 5. 注意事項

- 地デジ専用です。BS・CS は受けられません。
- 選局の直後は、復調器と FIFO が切り替わる間（0.5〜1.0 秒）、TS が乱れます。  
  既定ではこの間の出力を捨てます（`--no-settle` で無効にできます）。
- `--card-log` の記録には鍵の情報が入ります。人に渡さないでください。

## 6. 技術メモ

この節は実装のときに調べた機器の中身の記録です。

### 6.1 ハードウェア・USB インターフェース

| 項目 | 値 | 備考 |
|---|---|---|
| USB VID / PID | `1c11:1004` | `lsusb` の USB ID DB 上は別ベンダー名（Input Club Inc.）と表示される場合があるが、DY-UD200 固有の ID |
| USB 速度 | High-Speed (480 Mbps) | Bus Powered 500 mA |
| `bcdDevice` | `1.00` | ロット・FW バージョンに関わらず固定。FW 版はコマンド `0x9f` で取得する |
| インターフェース | Interface 0 (Vendor Specific) | カーネルドライバーは存在せず、ユーザー空間から `usbfs` 経由で直接制御 |
| エンドポイント `0x02` (OUT) | Bulk, 512 bytes | 制御コマンド送信（132 バイト固定長） |
| エンドポイント `0x84` (IN) | Bulk, 512 bytes | 制御応答受信（128 バイト固定長） |
| エンドポイント `0x86` (IN) | Bulk, 512 bytes | MPEG-2 TS ストリーム受信 |
| 受信放送波 | 地上デジタル放送（ISDB-T）専用 | UHF 13〜62ch / VHF 1〜12ch / CATV C13〜C63ch（ワンセグ対応） |
| B-CAS スロット | 本体内蔵 | USB 制御コマンド（`0xf0`）越しに APDU を直接中継 |

### 6.2 USB 制御コマンドプロトコル

#### フレーム構造

- **送信フレーム（132 バイト）**
  - `[0..127]`: 平文コマンド本体（不足分は `0x00` パディング）
    - ヘッダー 4 バイト: `<種別> 0xf0 <命令番号> <ペイロード長>`
    - 種別 `0x0f`: 初期化コマンド（セッション開始時のみ）
    - 種別 `0x1f`: 通常コマンド
  - `[128..131]`: `[0..127]` に対する IEEE CRC32（ビッグエンディアン）
  - **暗号化**: 先頭 2 バイト（`[0..1]`）と末尾 2 バイト（`[130..131]`）は平文のまま残し、間の 128 バイト（`[2..129]`、16 バイト × 8 ブロック）を AES-ECB で暗号化する。
    - 種別バイトの bit 4（`0x10`）が `0` の場合: 既定の 32 バイト鍵による **AES-256-ECB** で暗号化し、同時に平文コマンドの `[16..31]`（16 バイト）を以後のセッションコマンド鍵に設定する。
    - bit 4（`0x10`）が `1` の場合: 設定済みの 16 バイト鍵による **AES-128-ECB** で暗号化する。

- **応答フレーム（128 バイト）**
  - 128 バイト全体を既定の 32 バイト鍵による **AES-256-ECB** で復号する。
  - `[124..127]`（ビッグエンディアン）が `[0..123]` の IEEE CRC32 と一致することを検証する。
  - `res[0]` がステータス（`0x00` = 成功）、`res[1]` が応答データ長を示す。

実装は [internal/dyud200/crypto.go](../internal/dyud200/crypto.go) にあり、`dy-ud200-tools.h` の公式テストベクタを用いた単体テスト（[internal/dyud200/crypto_test.go](../internal/dyud200/crypto_test.go)）で一致を確認しています。

#### 主要コマンド一覧

| 操作 | 平文コマンド先頭バイト列 | 応答 | 備考 |
|---|---|---|---|
| 初期化（旧 FW） | `0f f0 e0 20 00 00 00 00 23 8d c0 d0 0e d0 38 75 ...`（34 バイト） | 128 B | 起動直後に送信 |
| 初期化（FW 1.0.5-2） | `0f f0 e0 20 00 00 00 00 7b 36 51 e5 21 7c 7b 1c ...`（34 バイト） | 128 B | FW `1.0.5-2` 検出時に再初期化で使用 |
| 新 FW 用初期化 | `1f f0 e3 04 00 00 00 00` | 2 B | 旧 FW ではエラー応答が返るが、無視して続行 |
| クローズ | `1f f0 e2 04 00 00 00 00` | 2 B | 終了時・再初期化前に送信 |
| FW バージョン取得 | `1f f0 9f 04 00 00 00 00` | 6 B | `res[2..5]` が `major.minor1.minor2-minor3` |
| シリアル取得 | `1f f0 95 04 00 00 00 00` | 18 B | `res[2..17]`（最大 16 文字、非 ASCII 除去） |
| セグメント設定 | `1f f0 d1 04 SS SS SS SS` | 1 B | フルセグ `0x00020000` / ワンセグ `0x00010000`（BE） |
| TS XOR 鍵設定 | `1f f0 30 20 <暗号化済み 32B 鍵>` | 1 B | 既定 XOR 鍵で変換した 32B セッション鍵を設定 |
| 周波数設定 | `1f f0 d2 06 FF FF FF FF` | 1 B | 中心周波数（kHz、BE）。UHF は `473143 + 6000*(ch-13)` |
| ロック状態取得 | `1f f0 b1 04 26 0a 00 00` | 4 B | `res[3] > 8` でロック完了 |
| 信号強度取得 | `1f f0 d5 04 00 00 00 00` | 6 B | `res[2..5]` を取得（目安値換算） |
| TS 開始 / 停止 | `1f f0 b4 04 ...` / `1f f0 b5 04 ...` | 1 B | ストリーミング制御 |

#### 初期化シーケンス（FW 1.0.5-2 対応）

1. `cmdInit`（34 B）→ `StopTS` → `cmdInitNF`（`0xe3`）
2. `GetFirmwareVersion`（`0x9f`）で FW 版を確認
3. FW が `1.0.5-2`（`0x01000502`）の場合は、`cmdClose` → `cmdInitNew`（34 B）→ `StopTS` → `cmdInitNF` で再初期化
4. `GetSerial`（`0x95`）→ `SetSegMode(FullSeg)`

### 6.3 TS ストリーム処理と品質安定化

#### TS パケットの XOR 復号

無改造の純正ファームウェアでは、選局時にコマンド `0x30` で設定した 32 バイトのセッション XOR 鍵から 256 バイトの LUT を生成し、TS ストリーム内の対象パケットを XOR 復号します（[internal/dyud200/crypto.go](../internal/dyud200/crypto.go)）。

復号対象となる条件（`BonDriver_dyud.cpp` 準拠）：
- `0x0010 <= PID < 0x1fff`
- `transport_scrambling_control >= 2`
- `transport_priority == 1`（復号時に `0` へクリアし、ペイロード先頭 128 バイト `[4..131]` を変換）

パッチ済みファームウェアなどで XOR がかからない場合は、`--no-xor` で鍵設定と復号を無効化できます。

#### USB 受信と選局直後の過渡期対策（`Settler`）

実機（FW `1.0.5-2`）の計測により、以下の特性が確認されました：
1. **URB バッファサイズ**: `24064` バイト（`47 × 512` = USB High-Speed Bulk 最大パケット長の倍数、かつ `128 × 188` = TS パケット長の倍数）の URB を 16 個使って非同期で受信すると、定常時の USB ドロップを 0 に維持できます。
2. **選局直後の 0.5〜1.0 秒間の過渡現象**: 選局・ロック直後は復調器と内部 FIFO の切り替えにより、4096 バイト単位の欠損（148 + 40 バイトの同期ズレや CC 飛び）が発生しますが、約 1 秒経過後は完全に安定します。
3. **安定化フィルター（[internal/dyud200/settle.go](../internal/dyud200/settle.go)）**:
   - ロック直後の 2048 パケット（385,024 バイト）を読み捨てたのち、`0x47` が 4 回連続する位置で厳密に同期をとります（[internal/dyud200/stream.go](../internal/dyud200/stream.go)）。
   - さらに `Settler` が **PAT（PID `0x0000`）の受信を確認しつつ、非 NULL パケットで TEI・CC 飛び・再同期のない状態が 15,000 パケット（約 1.2 秒分）続く**まで出力を保留し、安定した先頭から流し始めます。
   - これにより、録画開始直後のドロップ・PCR 飛びを除去しつつ、定常運用時のゼロドロップを実現しています。

### 6.4 内蔵 B-CAS カードスロット制御

DY-UD200 本体の B-CAS スロットは、制御コマンド `0xf0` 経由で直接 APDU を送受信できます（[internal/dyud200/card.go](../internal/dyud200/card.go)）。

- **コントローラーリセット**: `1f f0 f0 05 02 00 42 00 00` → `1f f0 f0 05 02 00 41 00 00`
- **APDU 中継**:
  `1f f0 f0 <n+9> 02 00 31 00 <n+4> 00 <cycle> <n> <APDU...> <parity>`
  - `cycle`: 送信ごとに `0x00` と `0x40` を交互に切り替える
  - `parity`: `[10]` から APDU 末尾までの XOR パリティ
  - 応答は `res[6]` が応答長、`res[7 : 7+len]` がカードからの応答バイト列

外付けの PC/SC リーダーを使用したい場合は `--b25 --pcsc`（環境変数 `PCSCLITE_CSOCK_NAME` 対応）で切り替え可能です。
